## Что представляет собой проект

Сайт лиги Gata Blood Bowl / Sevens в Ереване: двуязычный справочник EN/RU,
конструктор и сохранённые ростеры, профили тренеров, сезоны, расписание,
товарищеские вызовы, подготовка к матчу и послематчевое развитие команды.
Отдельный прототип `/play` позволяет играть выставочные матчи на виртуальном поле.

Стек: браузерный JavaScript без фреймворка, ES-модули, HTML/CSS, собственный
hash-router; сервер на `node:http`, PostgreSQL и `pg` — единственная зависимость
в `package.json`. Тесты используют встроенный `node:test`. Playwright необязателен
и не входит в зависимости проекта.

## Поведение лиги, которое важно учитывать

- Подготовка матча: болельщики, погода, состав и необязательные journeymen,
  inducements, подтверждение обеих сторон. Можно выйти неполным составом.
  Kick/receive в checklist лиги не входит: его решают за столом. Mercenaries
  пока недоступны до определения правил найма.
- Старт сохраняет снимки составов и тратит казну один раз. Начатый матч использует
  сохранённый снимок, а не произвольно меняющийся текущий ростер.
- Post-match хранит черновики результата, доходов, Dedicated Fans, статистики,
  травм, MVP, прокачки, состава и финансов до подтверждения обоими тренерами.
  Завершение применяет обе команды и результат транзакционно; версии и receipts
  защищают от повторного начисления денег/SPP. Старые матчи без снимков используют
  прежнюю форму результата.
- Товарищеские матчи проходят тот же цикл и меняют ростеры, SPP и казну, но дают
  **0 LP**, не входят в сезонную таблицу и расписание.
- Выход из сезона помечает запись `withdrawn_at`, сохраняя матчи и статистику.
  Не следует возвращать удаление истории как способ снять участника.
- MVP даёт **5 SPP**; прокачку можно отложить. Бонус за полностью покрашенную
  команду — **15k**. Постоянные Mortuary Assistant / Plague Doctor стоят **50k**
  и добавляют **50k** к TV/CTV; их разовые inducements стоят **100k**.
- Суммы хранятся в тысячах; `sumMoney()` складывает через целые золотые монеты,
  чтобы сохранять точность дробных сумм при продаже игроков.

## Виртуальное поле `/play`

Это отдельное приложение с английским интерфейсом. В составе сайта вход в аккаунт
нужен для выбора команд из БД; доступны любые сохранённые команды, а не только
команды вошедшего тренера. Сервер заново читает выбранные ростеры при создании
матча, принимает ID команд/игроков и не доверяет переданным характеристикам.

Поддерживаются local hotseat и комнаты на двоих. Сервер комнат применяет команды,
генерирует кубики, проверяет версии/очерёдность и раздаёт состояние по SSE.
Комнаты существуют только в памяти: исчезают при перезапуске и удаляются после
двух часов простоя без подключённых клиентов. Выставочные игры **не записывают**
результаты, SPP, казну или изменения ростеров в лигу.

Основной цикл: поле 20 × 11, полный ростер со скамейкой, до семи игроков на поле,
до четырёх специалистов и минимум три Linemen при наличии, расстановка перед
каждым drive, осенняя погода, kick/receive, kickoff events, движение, блоки,
короткие передачи, touchdown, turnovers, KO recovery, два тайма по шесть ходов.
Кубики проходят Roll → необязательный reroll → Confirm; решение о follow-up
при блоке принимается до armour/injury и отскока мяча.

Полный движок правил пока не реализован: нет foul, interception, полной геометрии
передач, long pass, Throw Team-mate, apothecary и покупки inducements; Bribes
считаются, но не расходуются. Автоматизированы Block, Dodge, Evasive, Tackle,
Pass, Sure Hands и Catch; остальные импортированные навыки служат справкой.
Подробные ограничения и управление — в [play-demo.md](play-demo.md).

Внешний вид двух приложений различается: у лиги шесть тем и общие Matchday-компоненты;
у демо восемь палитр, Barlow/Barlow Condensed, свои `palettes.*`, `themes.mjs`,
`theme-boot.js` и CSS. Изменение темы одного приложения не обновляет автоматически другое.

## Запуск и сборка

| Команда | Режим и адрес по умолчанию |
|---|---|
| `npm run dev` | Справочник из исходников, `http://localhost:5173`; без API и БД |
| `npm start` | Сборка + сайт/API/PostgreSQL, `http://localhost:3002`; `/play` доступен здесь же |
| `npm run server` | Только сервер: использует существующий `dist/`, иначе исходники |
| `npm run demo` | Отдельное демо и комнаты с учебными командами, `http://localhost:5174`; без БД |

В PowerShell при блокировке `npm.ps1` использовать `npm.cmd`.
Первичная настройка лиги: `npm ci`, копия `.env.example` в `.env`,
`npm run postgres:up`, `npm run db:migrate`, `npm start`.
Сервер проверяет применение миграций, а не выполняет их на каждом запуске.
Последняя миграция в этом снимке — **008**, хотя раздел релиза 2.0.0 описывает 005–007.

После изменения `src/`, `content/` или ресурсов при работе через основной сервер
нужно пересобрать `dist/` и обновить браузер. После изменения серверного кода нужен
перезапуск API; новые миграции применяются до него. `public/data*.json` и `dist/`
генерируются. `public/play.html` написан вручную и является исходником.

Сборка синхронизирует версии импортов и ресурсов, объединяет/минифицирует CSS лиги.
Изменения стилей проверяются и на собранном сайте. `.env` выбирается в порядке:
`BLOODBOWL_ENV_FILE` → `/etc/bloodbowl-league/.env` → файл в корне репозитория.
Статика отдаётся по allowlist из `server/http/static-path.mjs`.

В `.github/workflows/deploy.yml` настроен деплой `main` на VPS через SSH:
build → migrations → PM2 restart → health check; при неудаче откатывается код.
Эксплуатация и резервные копии описаны в [DEPLOYMENT.md](../DEPLOYMENT.md).
Настройка этого workflow сама по себе не доказывает текущую версию production.
