## Проект и код

Сайт лиги Gata Blood Bowl / Sevens в Ереване: справочник EN/RU, ростеры,
профили тренеров, сезоны, пары, товарищеские матчи, подготовка и post-match.
Отдельное приложение `/play` — выставочные игры на виртуальном поле.

Стек: браузерный JavaScript без фреймворка, ES-модули, hash-router, HTML/CSS.
Сервер использует `node:http`, PostgreSQL и `pg`; тесты — встроенный `node:test`.

## Исправления матчей

Каждый тренер заполняет **только свою команду**. Собственные pre-match и
post-match чеклисты проходят без подтверждений соперника между шагами.
Погода и счёт общие; старт и завершение требуют готовности обеих сторон.
Изменение зависимого бюджета или дохода возвращает затронутый шаг на проверку.
Старые черновики, ожидающие подтверждения счёта, обновляются при чтении.

Ростер прематча актуализируется при открытии подготовки, включая прокачку,
SPP, найм, травмы и ресурсы. Создание пар не фиксирует состав. Проверяются
данные команды, а не только `revision`. Старт проверяет актуальность под
блокировками и сохраняет снимки; после старта они не обновляются.

На Players справа от Injury есть «Change records» / «Изменить записи».
Кнопка открывает счётчики и травмы игрока; после закрытия шага — только чтение.
После изменения счётчиков, MVP, покупок и бросков список матчей не перечитывается
без необходимости. Изменения стадий и завершение обновляют связанные экраны.
Чтение неизменившегося pre-match/post-match не перезаписывает БД.

На Players и Roster одна кнопка «Далее» переводит дальше после успешного
сохранения. Прокачивать всех или совершать покупки необязательно; непотраченные
SPP и выбранные улучшения сохраняются. Выбор MVP тоже необязателен: возле
«Далее» чеклист напоминает выбрать MVP и прокачать игроков, отмечая сделанное.
Можно продолжить без обоих действий. Согласованность TD/CAS со счётом,
доступность выбранных MVP и обязательные броски ветеранов проверяются.

На шаге Next действующий капитан показан без повторного выбора. Капитанство
сохраняется до смерти, включая травмы, пропуск матча и временный уход. После
смерти (с учётом защиты новичков) либо при отсутствии первоначального назначения
нужно выбрать капитана явно. Сервер сохраняет действующего капитана также при
завершении старого незаконченного чеклиста, в котором была выбрана замена.

Завершение применяет обе команды и результат транзакционно, с защитой от
повторного начисления. Товарищеские матчи меняют ростеры, но дают 0 LP.
Выход из сезона сохраняет матчи и статистику через `withdrawn_at`.

Отдельная незавершённая проверка: матч Spartak Arabkir во втором туре.
Пользователь сообщил поражение 0–1 от Snotling; точный соперник и CAS
не подтверждены. Исправления интерфейса не восстанавливали этот матч в БД.

## Виртуальное поле `/play`

Английский интерфейс, local hotseat и комнаты на двоих. Команды из БД доступны
после входа. Сервер перечитывает выбранные ростеры и принимает ID команд/игроков,
не доверяя характеристикам от клиента. Выставочные матчи не изменяют записи лиги.

Комнаты в памяти, синхронизация через SSE, серверные кубики и проверка версий.
После перезапуска комнаты исчезают; без подключений истекают через два часа.
Поле 20 × 11, скамейка, до семи игроков, расстановка, осенняя погода, kickoff,
основной цикл ходов и интерактивные кубики. Полный набор правил не реализован;
подробности и ограничения — [play-demo.md](play-demo.md).

Лига использует Golos Text/Oswald и восемь палитр v3. Демо использует отдельные
Barlow/Barlow Condensed, палитры и CSS; его стили не загружаются в приложение лиги.
`localStorage` обёрнут так, чтобы блокировка самого свойства не мешала запуску.

## Запуск и проверки

| Команда | Режим |
|---|---|
| `npm run dev` | Справочник из исходников, порт 5173, без API |
| `npm start` | Сборка + сайт/API/PostgreSQL, порт 3002, включая `/play` |
| `npm run server` | API и существующий `dist/`, иначе исходники |
| `npm run demo` | Учебные команды и комнаты без БД, порт 5174 |

Миграции применяются явно: `npm run db:migrate`; запуск проверяет схему.
`dist/` и `public/data*.json` генерируются. `public/play.html` — исходник.
После изменения клиента пересобирать `dist/`, сервера — перезапускать API.
Настройки выбираются через `BLOODBOWL_ENV_FILE`, `/etc/bloodbowl-league/.env`,
затем `.env` в корне. Статика отдаётся только по allowlist.

Стандартные проверки: `npm run build`, `npm run check`, `npm run i18n:check`,
`npm test`. Сборка: 288 EN + 288 RU страниц, 0 fallback. Проверки с БД включаются
через `GATA_TEST_DATABASE_URL` и используют временные базы. Часть файловых и
браузерных тестов рассчитана на Linux; полный набор проверяется в Linux-контейнере.
При объединении: 4427 тестов, 4043 прошли, 384 пропущены, 0 ошибок.
Пройдены сборка, check, i18n и Chrome-проверка списка команд и собранного `/play`
при ширине 390/1440 px. Ранее исправления чеклистов проверены с временной PostgreSQL.
После необязательного MVP: 4430 тестов, 4045 прошли, 385 пропущены, 0 ошибок;
отдельно прошли 4 проверки с временной PostgreSQL, включая завершение без MVP
и отсутствие повторного начисления. Чеклист и переход проверены в Chrome EN/RU.
После исправления капитанства на отдельной копии main: 4439 тестов, 4052 прошли,
387 пропущены, 0 ошибок. Две проверки с временной PostgreSQL подтверждают
сохранение живого капитана и назначение нового после смерти. Экран Next проверен
в Chrome на 390/1440 px, EN/RU.

Пуш в `main` запускает `.github/workflows/deploy.yml`: сборка, миграции,
перезапуск PM2, health check и откат кода при ошибке. Ветка
`codex/season-history-recovery` содержит служебную диагностику истории;
её workflow заменяет деплой и не является изменением приложения для слияния.
