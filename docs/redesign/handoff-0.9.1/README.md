## Как пользоваться прототипами

- Прототип — **эталон вида и поведения**, а не код для копирования. Разметка там на инлайн-стилях и маленьком рантайме (`x-dc`, `{{hole}}`, `sc-for`, `sc-if`) — в приложение это не переносится. В коде всё собирается из `src/ui/*` на токенах (`tokens.css`), с `t()` и `escapeHtml`.
- Розовая пунктирная рамка и розовые плашки «0.9 · …» — разметка ревью, в код не переносить.
- Данные в прототипах — пример (команда Ashgrove Wardens, тур 7). `[ЗНАЧЕНИЯ В СКОБКАХ]` — заглушки.
- **Правила и числа берутся из кода и контента, не из макетов** (§0.1 проектной спецификации). Если прототип и `src/domain/**` / `content/Gata/**` расходятся — прав код; известные расхождения перечислены в спецификации интерфейса («Известные расхождения»).
- Тексты интерфейса в прототипах — русские. Для каждой строки нужен ключ в `src/i18n/en.json` и `src/i18n/ru.json`; русский текст берите из прототипа или спецификации интерфейса, английский пишите по смыслу (термины Blood Bowl — как в `docs/i18n-glossary.md`).

## Ключевые решения (полностью — §0 проектной спецификации)

1. Правила — из кода и контента лиги. Броски на сайте необязательны (прокачка), MVP на сайте не бросается.
2. Ветка `redesign` + этапные PR из `rd/NN-название`; в `main` — одним PR на этапе 13.
3. Тренер может править казну напрямую; журнал пишет всё.
4. Все текущие команды — `active`; стадия `draft` включается вместе с админкой (этап 12).
5. Палитры 0.8 заменяют шесть тем 2.0.
6. Roster-блоб не переписывается, только аддитивные поля; новое — в новых таблицах.
7. **Действия в матче хранятся записями** (`match_events`, §3.7): тап во время матча сразу виден в карьере, сам подставляется в итоги, в блоб попадает один раз при завершении итогов. Из записей строится история игрока по матчам.
8. **Один путь к матчу:** подготовка → игра → итоги по шагам. Нет «Начать матч» на карточке, нет «Отменить начало», нет окна счёта вне итогов.
9. **Во время матча** в составе доступны только счётчики и «Травма в матче»; найм, продажа, прокачка и казна — после итогов. Во время подготовки правки разрешены с предупреждением.

**Открытый вопрос (§9.6):** оставить ли тренеру быстрый ввод счёта без подготовки. До ответа не удаляйте `proposeGameResult` и не рисуйте для него новый UI.

## Правила работы в репозитории

- Vanilla ES-модули, без фреймворка и сборщика; хешевый роутер; CSP без inline JS.
- Все строки — через `t("key")` и `data-i18n*`; `escapeHtml` на каждую интерполяцию.
- `src/domain/**` чистый: без DOM, storage, сети, глобалов (`npm run check`).
- Бюджеты: 600 строк на файл, 80 на функцию (`scripts/check-budgets.json`), только уменьшаются. Ноль недостижимых функций.
- Миграции не правятся после применения — только новой миграцией.
- Если меняется `content/Gata/**`, синхронно меняется `content/Gata-ru/**` (корневой `CLAUDE.md`).
- Перенесённый экран удаляет свой старый CSS в том же PR.
- Коммиты — на этапной ветке; пуш и PR делает владелец (или по его явной просьбе).
