# Стартовые промпты для Claude Code

Каждый этап — отдельная сессия и отдельная ветка `rd/NN-название` от актуальной `redesign`. Перед стартом: `git checkout redesign && git pull && git merge main` (если в `main` были фиксы), затем `git checkout -b rd/NN-название`.

Общий префикс для любого этапа:

> Мы делаем редизайн Gata League 3.0. Прочитай `docs/redesign/handoff-0.9.1/README.md`, затем план `docs/superpowers/plans/2026-10-14-redesign.md` (этап N), проектную спецификацию `docs/superpowers/specs/2026-10-14-redesign-design.md` (разделы, на которые ссылается этап) и корневой `CLAUDE.md`. Правила и числа бери из `src/domain/**` и `content/Gata/**`, вид и тексты — из прототипов в `docs/redesign/handoff-0.9.1/prototypes` и спецификации интерфейса `docs/superpowers/specs/2026-10-14-ui-spec-v0.9.md`. Работай в ветке `rd/NN-…`, коммить по пунктам плана, отмечай чекбоксы в плане. Перед завершением пройди `docs/redesign/handoff-0.9.1/PR-CHECKLIST.md`. Пуш, PR и слияние — по протоколу мастер-плана `docs/superpowers/plans/2026-10-14-redesign-rollout.md`.

## Этап 2 · БД и домен (`rd/02-data`)

> Этап 2 плана: миграции 009–014 и чистые доменные модули, без UI. Пункты 2.1–2.7, каждый отдельным коммитом с тестами. Особое внимание 2.6 (§3.7): `match_events`, `src/domain/post-match/events.mjs` (`statisticsFromEvents`, разница статистики и записей, карьера = блоб + неучтённые), `createPostSide` берёт статистику и травмы из записей, `finishPost` ставит `settled_at` и переносит неучтённые ручные записи в той же транзакции, что `applyPostMatchRoster`. Тесты: двойного счёта нет; journeyman из снимка получает записи; ревизия команды во время матча не меняется; старые блобы читаются без изменений.
