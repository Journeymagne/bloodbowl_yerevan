# Этап 05 · Оболочка и маршруты — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** дать сайту оболочку 3.0 — маршруты с таблицей редиректов, активную команду, мобильную шапку с вкладками, SideNav с карточкой текущего матча, экран входа `#/login` и настройки `#/settings` — поверх экранов 2.x, которые переносят этапы 06–12.

**Architecture:** все решения «какой экран и куда перенаправить» принимают чистые функции `src/core/routes.mjs` (`matchRoute`, `resolveRedirect`), а `src/core/router.mjs` только применяет их и рисует: новые имена маршрутов пока ведут на экраны 2.x (таблица «Маршруты этапа 05»). Состояние вошедшего тренера собирают модули `src/data/` — сессия (`/me` и `/api/teams` вместе), настройки аккаунта (тема: сервер важнее кеша), активная команда (маршрут → аккаунт → кеш → первая). Оболочка `src/shell/` — чистая модель навигации, разметка шапки и SideNav на `src/ui`, и тонкая DOM-склейка, которая перерисовывает их через `patch()` на каждом маршруте; новые экраны `src/screens/auth/` и `src/screens/settings/` собраны из компонентов этапа 04.

**Tech Stack:** vanilla ES-модули в браузере, хешевый роутер, Node 22 (`node --test`), `test/helpers/fake-dom.mjs`, CSS custom properties, нативный `<dialog>`; инструмент снимков этапа 04 (`npm run screens`, Chrome DevTools Protocol).

**Spec:** спека 3.0 `docs/superpowers/specs/2026-10-14-redesign-design.md` — §0, §1, §2 (маршруты и редиректы, активная команда), §3.5, §4 (строки `/api/auth/*`), §5, §6, §7. Спецификация интерфейса `docs/superpowers/specs/2026-10-14-ui-spec-v0.9.md` — §0 (шапка, навигация), §1 (навигация гостя), §2 (вход), §27–28 (настройки). ## Global Constraints

- Ветка `rd/05-shell` от свежей `origin/redesign` после слияния этапа 03 (зависимости этапа: 04 и 03). PR в `redesign` по протоколу мастер-плана, шаги 6–10. В задачах ничего не пушить.
- Каждый PR зелёный: `npm test && npm run check && npm run i18n:check && npm run build`; для 05 — плюс `npm run smoke`. `npm run build && npm run i18n:check` — одинаковое число страниц EN/RU, 0 fallback. Перед `npm test` всегда `npm run build` (тесты читают `public/data.*.json`).
- Vanilla ES-модули, без фреймворка, сборщика, TypeScript и новых зависимостей; хешевый роутер.
- CSP прода: ни inline JS, ни `style="…"`, ни `on…=` в разметке. Цвета SVG — классами и токенами, не hex в атрибутах.
- Каждая строка интерфейса — через `t("key")` или `data-i18n*`; ключ в `src/i18n/en.json` и `src/i18n/ru.json`, без дублей. В новых модулях ключи — литералами `t("…")`; ключ из шаблонной строки (`theme.palette.${key}`) получает тест, перебирающий все значения.
- `escapeHtml` на каждую интерполяцию строки; пропс `…Html` — только разметка другой функции `render…()`.
- Бюджеты `scripts/check-budgets.json`: 600 строк на файл, 80 на функцию, 0 недостижимых функций; `src/app.js` — не больше 160 строк (бюджеты только уменьшаются).
- `scripts/check-references.mjs` читает ключ объекта `xy:` как использование имени без последней буквы: ключ, равный экспорту проекта плюс один символ (`to:` → `t`, `views:` → `view`, `icons:` → `icon`, `states:` → `state`), ломает `npm run check`. Такие ключи не заводить.
- Правила и числа — из кода (`server/`, `src/domain/**`, `content/Gata/**`), вид — из прототипов. Расхождение макета с кодом правится по коду без вопроса (спека 3.0 §0.1, §0.12).
- Брейкпоинты: мобильная раскладка до 900px (`max-width: 900px`), десктоп от 901px (`min-width: 901px`). Нажимаемое — от 44px.
- `gata-league-auth-token` и формат сессий не трогать: никто не должен перелогиниться (мастер-план, 05). Новый ключ хранилища — только `active-team` в `STORAGE_KEYS`. Писатель `gata-league-palette` — по-прежнему только `src/core/theme.mjs`.

## Review Focus

1. **Палитра на двух устройствах.** Устройство без выбора (по умолчанию) входит первым — аккаунт не должен получить палитру по умолчанию и затереть выбор, сделанный на другом устройстве; аккаунт с палитрой перекрашивает браузер. Task 5, тесты «a browser that never chose sends nothing…» и «an account that has a palette repaints this browser…».
2. **Гость по ссылке из Telegram на страницу тренера** (`#/my-teams/<id>`, `#/t/<id>/roster`, `#/my-games`) → вход → возвращается именно туда, а не на `#/`; старый адрес не остаётся в истории, редиректы не зацикливаются. Task 3, тесты «a guest is sent to sign in and brought back…» и «no redirect loops…».
3. **Только что созданная или удалённая команда.** Переход в команду, которой ещё нет в загруженном списке (сохранение в билдере), перечитывает список, а не отправляет на `#/teams`; удаление активной команды переводит шапку на другую и не пишет в аккаунт мёртвый id. Task 6, тесты «a team created a moment ago…» и «the active team deleted elsewhere…».
4. **Нет сети или 502 при старте.** `/me` падает без 401 (деплой, метро): токен остаётся, следующая загрузка возвращает тренера; 403 любого маршрута не выкидывает из аккаунта. Task 1 и Task 2, тесты «a refusal (403) is not the end of the session» и «no network at start keeps the token…».
5. **Статья справочника, затенённая маршрутом 3.0.** Страница, чей slug совпал с новым маршрутом (`teams/new`, `login`, `settings`, `ref/…`, `t/…`, `coaches/…`), пропала бы без следа. Task 3, тест «every reference page still opens at its own address» по `public/data.en.json` и `data.ru.json`.

## Решения этого плана

Источники оставили их открытыми; план принимает их так (контроллер подтверждает до исполнения):

1. **Маршруты 3.0 рисуют экраны 2.x до своего этапа** (таблица «Маршруты этапа 05»). Почему: таблица маршрутов, вкладки и ссылки пишутся один раз; этапы 06–12 меняют только рендерер имени.
2. **Билдеры ссылок отдают новые адреса**, литералы старых адресов в `src` заменены билдерами. `#/my-games` остаётся псевдонимом «матчи активной команды»: адреса без id команды для них нет. Почему: редиректы — для внешних ссылок, внутренние не должны ходить через них.
3. **Всё «куда ведёт адрес» — одна чистая функция** `resolveRedirect(route, {signedIn, activeTeamId, returnTo}) → {target, returnTo}`: старые адреса, гость на странице тренера (вход с запоминанием адреса), вошедший на `#/login` (на запомненный адрес или `#/`), тренер на `#/` (обзор активной команды). Роутер применяет `location.replace`. Почему: тестируется без DOM, циклы ловит тест, старый адрес не остаётся в истории.
4. **`#/teams`:** тренеру — «Мои команды» (спека §2), гостю — редирект на `#/ref/teams`: по этому адресу в 2.x жил каталог «Правила команд», и старая ссылка гостя должна вести туда же.
5. **Только для вошедших:** `teams`, `team*`, `coach`, `coachTeam`, `game`, `preMatch`, `postMatch`, `administration*`. `#/teams/new` до этапа 06 открыт гостю: билдер 2.x хранит черновик локально и при сохранении отправляет на вход. `#/settings` открыт гостю: «Оформление» и язык, вместо «Аккаунта» — вход и регистрация (вопрос владельцу 2).
6. **Сессия:** только 401 значит «сессии нет», 403 — отказ, который объясняет экран (баг этапа 03). `/me`, упавший без 401, оставляет токен. После `POST /api/auth/login` и `/register` всегда идёт `/me`: в ответе входа нет `preferences`. `/me` и `/api/teams` запрашиваются вместе.
7. **Активная команда:** id из маршрута `#/t/:id/*` → `preferences.activeTeamId` (сервер уже отбросил чужую и удалённую) → кеш `gata-league-active-team` `{userId, teamId}` → первая команда списка (`ORDER BY updated_at DESC`). Каждый кандидат проверяется по списку команд тренера. `PATCH` — только когда итог отличается от аккаунта. Выход стирает кеш; кеш другого тренера не читается.
8. **Тема:** сервер важнее кеша, недостающие поля берутся из локального выбора; в аккаунт всегда пишутся все три ключа; выбор по умолчанию в аккаунт не пишется (передача 04, спека выката §5.4).
9. **Язык остаётся локальным** (`gata-league-locale`, спека выката §5.4 «без изменений»), `preferences.locale` этап не пишет. Переключатель: низ SideNav (десктоп) и «Настройки → Оформление» (мобайл); `#lang-toggle` уходит.
10. **Сжатие шапки — по прокрутке документа** (`document.scrollingElement.scrollTop`), пороги 48/8 с гистерезисом. Почему: в прототипе прокручивается `main` внутри артборда, на сайте — документ; экраны 2.x (`season/admin.mjs` сохраняет `scrollY`, липкие заголовки) рассчитаны на прокрутку документа.
11. **Смена команды** в шапке и SideNav — ссылка на `#/teams` («Мои команды» 2.x). Шторка и поповер переключателя — этап 06 (флоу «Смена и создание команды»).
12. **Карточка текущего матча — в SideNav** (десктоп); на мобайле карточка живёт в «Обзоре» (06) и «Матчах» (09). Порядок: идёт игра → следующий матч текущего тура → счёт ждёт подтверждения. Действия 0.9: «Подготовка к матчу»; во время игры «Записи матча» (состав) и «Итоги матча».
13. **Числа форм — из сервера:** логин ≥ 3, пароль ≥ 4 (прототип смены пароля просит 8 — правится по коду, §0.1). Шкала надёжности — из прототипа регистрации: «Слишком короткий» < 4, «Нормальный» < 8, «Надёжный» ≥ 8. Константы — в `src/domain/account.mjs`, их же читает сервер.
14. **Telegram:** правило спецификации интерфейса §2 — `@` и от 5 символов `[A-Za-z0-9_]` (до 32, как у Telegram; регулярка прототипа `{4,}` расходится с его же подсказкой). `@` дописывается сам. То же правило — при смене контакта в настройках (вопрос владельцу 3). Сервер не меняется.
15. **Логин в настройках только для чтения** (прототип, README дизайн-системы: «login (read-only)»); смена логина остаётся админке.
16. **Экран входа без панели «Вы вошли»:** после входа роутер ведёт на запомненный адрес или `#/`. `h1` — название формы («Вход» / «Регистрация»; на мобайле визуально скрыт, его называет переключатель), строка-призыв десктопа — `p`.
17. **Значения полей форм живут в состоянии экрана и рисуются в `value`:** `patch()` возвращает поле без фокуса к значению разметки, и пустой `value` стёр бы введённое. Пароли стираются из состояния при закрытии шторки, после успеха и при уходе с экрана.
18. **Превью палитр** — те же блоки `tokens.css`: к селектору каждой палитры добавлен `[data-palette-preview="<key>"]`, превью ставит атрибут на свою внутреннюю часть. Почему: 8 палитр × 18 цветов не дублируются; кнопка карточки остаётся в текущей палитре (кольцо выбора и фокус).
19. **Фокус на тёмной полосе шапки и SideNav — цвета `--header-ink`.** Механизм тот же, что в `base.css` (`outline`); `--accent-text` на `--header` в светлых палитрах ниже 3:1 (`#2F7A52` на `#17392C`).
20. **Поиск 2.x** (`#global-search`) — статичная полоса над `#app-view`, видна только на списках справочника (`ref`, `refSection`): его читает только `section.mjs`, а поле вне перерисовки не теряет фокус. Этап 11 заменяет.
21. **Подвал** (дата данных, «неофициальный справочник», юридическая ссылка): низ SideNav на десктопе, конец `main` на мобайле.
22. **Блокировка прокрутки под шторкой** — в `src/ui/sheet.css`, а не в оболочке (заметка 05–13): правило относится к шторке, где бы её ни открыли.
23. **`setActiveNav` / `setViewSection`** в экранах 2.x остаются пустыми вызовами до переноса экранов; подсветку вкладки даёт маршрут. `routeSection` удаляется: его никто не вызывал, его заменяет модель навигации.
24. **Снимки:** состояния вошедшего тренера — на mock API (настройки mock отдаёт эхом и не хранит, поэтому каждый снимок начинается с одного аккаунта); реальный сервер — только гость: палитра из `preferences` админа перекрыла бы вариант снимка.
25. **Без форм множественного числа** («Тренер с 2025 · команд: 2»): `t()` их не знает.
26. **`test/screen-lifecycle.test.mjs`** (п. плана 3.0): тест про шапку ничего не знал; обновление — тесты границы «рамка ↔ экран» (Task 14).

## Вопросы владельцу

План не ждёт ответа: исполняется вариант по умолчанию, ответ «нет» снимает отмеченный шаг.

1. **Акцент «Пламя Хаоса» `#C2571A`:** белый текст на нём — 4.49:1, на волосок ниже AA (кнопки, кубик, «В», «+»). По умолчанию — затемнить до `#C1561A` (4.55:1) в `tokens.css` и на странице техобслуживания, как сделали с `--neutral-result` (Task 11, шаг 5).
2. **Гость и настройки.** В прототипах у гостя нет ни настроек, ни языка, ни «Войти» в шапке (вход — только с главной гостя, этап 11). По умолчанию — у гостя вкладка «Настройки» (оформление и язык) и ссылка «Войти» в шапке и SideNav: иначе гость теряет выбор темы и языка, который был в 2.x (Task 8, Task 12).
3. **Формат Telegram в настройках.** У части тренеров 2.x контакт не `@username`. По умолчанию — сохранить новый контакт можно только в формате регистрации; нетронутый контакт не проверяется (Task 8).
