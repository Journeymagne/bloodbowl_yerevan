# План рефакторинга: экраны, организация информации, билдер, сохранение ростеров

> **Редакция 2 от 2026-08-24.** План переписан целиком после сверки с кодом.
> Что именно изменилось и почему — раздел «Ревизия от 2026-08-24». Номера задач
> сохранены намеренно: на них ссылаются сообщения коммитов,
> `scripts/check-budgets.json`, design spec и разбор инцидента. Новая задача
> получила номер `7b`, а не сдвинула остальные.

**Цель:** превратить одностраничный монолит (`src/app.js` — на старте 7474 строки,
368 функций) в модульное приложение с одним редактором ростера, одним каноническим
форматом данных и надёжным сохранением — включая сохранение ростера в процессе
игры, которого сейчас нет.

**Архитектура:** vanilla JS + нативные ES-модули, без сборщика и без фреймворка.
`src/core/*` — инфраструктура, `src/domain/*` — чистая доменная логика
(переиспользуется сервером), `src/data/*` — слой хранения и синхронизации,
`src/screens/*` — экраны, `src/components/*` — переиспользуемые компоненты.
Сервер разбивается на `server/routes/*` с общим доменным модулем валидации.

**Проектное решение:** `docs/superpowers/specs/2026-08-19-app-refactor-design.md`.
Раздел 10.2 спеки (формат RosterV2) **отменён** — см. задачу 3.2.

Выполняй задачи сверху вниз по разделу «Порядок и зависимости». Одна задача = один
коммит = одно проверяемое состояние. Не начинай следующую, пока не выполнен блок

## Глобальные ограничения

- **Стек не меняется:** vanilla JS, нативные ES-модули, никаких бандлеров,
  транспиляторов, фреймворков и новых рантайм-зависимостей на фронте. Единственная
  зависимость сервера остаётся `pg`. Playwright — опциональный dev-инструмент, в
  `dependencies` не попадает.
- **i18n-правило из `CLAUDE.md` действует без исключений:** любая новая строка
  интерфейса идёт через `t("ключ")` + `src/i18n/{en,ru}.json`. Доменные функции
  возвращают **коды** нарушений (`ROSTER_MIN_PLAYERS`), а не готовый текст.
- **Правило зеркальности контента из `CLAUDE.md` действует:** `content/Gata/` и
  `content/Gata-ru/` имеют одинаковые имена файлов и папок после любой правки.
- **Перед коммитом контентных изменений:** `npm run build && npm run i18n:check`.
- **Данные пользователей священны.** Ни одна задача не имеет права терять
  сохранённые ростеры. Необратимых операций над блобами в плане не осталось
  (шаги 3.3 и 4.4 отменены); если такая появится — сначала задача 0.
- **Поведение UI не меняется до задачи 8.** Задачи 1–7 механические. Исключения
  оговариваются в самом шаге и коммитятся отдельно — так были сделаны вкладки
  сезона в URL (6.7), подсветка меню и метка локали (`7236d64`).
- **Тесты вводятся для `src/domain/**`, `src/core/**`, `src/data/**` и миграций**
  (встроенный `node:test`). Экраны проверяются браузерным прогоном:
  `scripts/browser-check.mjs` (публичные экраны) и `scripts/browser-check-roster.mjs`
  (редактор поверх `scripts/mock-api.mjs`).
- **Храповик `scripts/check-budgets.json` только понижается.** Поднять число можно
  ровно ради исправления бага или потери данных, и причина пишется в `_notes` того
  же файла. Дрейф — не причина.
- **Каждая задача заканчивается рабочим приложением:** `npm run build && npm start`,
  открыть `http://localhost:3002`, пройти `docs/smoke-test.md`.

## Чего этот план сознательно не делает

Переход на фреймворк, TypeScript или сборщик; редизайн визуального стиля и тем;
изменение содержания правил лиги; онлайн-трекер матча по ходам; смена хостинга или
БД; отдельная мобильная версия; шифрование и офсайт-копия бэкапов (риск записан в
`DEPLOYMENT.md`, решение за владельцем). Обоснование — раздел 12 design spec.
