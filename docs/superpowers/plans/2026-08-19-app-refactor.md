**Цель:** превратить одностраничный монолит (`src/app.js`, 7474 строки, 368 функций) в модульное приложение с одним редактором ростера, одним каноническим форматом данных и надёжным сохранением — включая сохранение ростера в процессе игры, которого сейчас нет.

Сервер разбивается на `server/routes/*` с общим доменным модулем валидации.

### Решения владельца

- **2026-08-21, бюджет 600k — константа лиги.** Это только деньги на
  изначальный закуп команды, полем сезона он не становится. `startingBudget`
  остаётся константой в `league-rules.mjs`; «остаток бюджета» для команды,
  уже играющей в лиге, бессмыслен и убирается шагом 7.5. Вопрос 1 раздела 13
  design spec закрыт.
- **2026-08-21, `skipNextGame` уменьшает TV — так и задумано.** Пропускающий
  игрок намеренно исключается и из состава, и из стоимости команды.
  `calculateRosterCosts` остаётся как есть, поведение помечено комментарием в
  коде. Вопрос 2 раздела 13 закрыт.
- **Вопрос 4 (прокачка и скиллы) переформулирован и ждёт ответа.** Речь о том,
  что в редакторе два независимых учёта: кнопка «Улучшение» тратит SPP и
  поднимает ранг, но не выдаёт ничего, а кнопки «Добавить навык» и статы
  выдают навык или характеристику **бесплатно** — ни SPP, ни казны, растёт
  только стоимость игрока. Проверено по коду: `spendTreasury` зовётся лишь
  при найме игрока и покупке персонала (см. поправку к 5.6 design spec — в
  первой редакции и там, и здесь ошибочно говорилось «стоят золота»).
  Вопрос владельцу: должно ли «Улучшение» стать единственным способом
  получить навык или стат — жмёшь, тратится SPP, тут же выбираешь, что
  получил. Нужен до шага 7.8.

### Найдено по дороге, ждёт решения владельца

- **Выбор типа прокачки при нуле SPP даёт бессмысленную ошибку.** Когда SPP не
  хватает ни на что, все варианты в списке отключены, значение `select`
  остаётся пустым, и кнопка «Улучшение» отвечает «Неизвестный тип прокачки: .».
  Раньше это был `alert`, поэтому и не бросалось в глаза. Ошибка честная, но
  говорит не то: причина не в неизвестном типе, а в нехватке SPP. Чинится
  вместе с интерфейсом выбора прокачки (шаг 7.8), который владелец отложил.

- **Подсветка меню разошлась.** `routeSection()` в `src/core/routes.mjs`
  выводит активный пункт меню из маршрута, но каждый экран дополнительно зовёт
  `setActiveNav()` сам, и значения не совпадают: профиль игрока
  (`players/…`) подсвечивает «season». `renderRoute` раньше вычисляла
  `routeSection(route)` и выбрасывала результат — отсюда и рассинхрон.
  Переход на единый источник — видимое изменение, поэтому отдельным коммитом.
- **Метка переключателя языка и дата в футере не обновляются при смене локали.**
  `applyLocaleChrome()` (метка `lang-toggle`, её `title`, локаль даты в футере)
  зовётся только из `init()`. `switchLocale()` меняет локаль и перерисовывает
  маршрут, но хром не трогает, а у кнопки нет `data-i18n`, поэтому
  `applyStaticI18n()` до неё не достаёт: после переключения на английский
  кнопка продолжает предлагать «EN». Баг не новый — код `switchLocale`
  побайтово тот же, что до задачи 6.9; починка в одну строку, но это видимое
  изменение поведения, поэтому отдельным решением.
- **Фильтр инducements ничего не фильтрует.** У панели ровно два варианта —
  «все» и «Inducement», а тег `Inducement` стоит у всех 24 страниц, поэтому
  оба дают одинаковый список. Панель занимает место и ничего не делает. Либо
  фильтровать по чему-то осмысленному, либо убрать — соседний случай с 4.3
  design spec.
- **`public/data.json` в гите содержит `generatedAt`.** Любая сборка даёт диф
  в этом файле. Либо убрать файл из индекса (он генерируется `npm run build`),
  либо убрать метку времени.

### Починено по дороге

- **`playerAdjustmentCost` читала `player.row`**, хотя соседняя
  `playerCurrentCost` принимает `row` параметром. Пара работала только на
  копии из `rosterPlayerView` и падала на сыром игроке черновика с
  `Cannot read properties of undefined (reading 'skills')`. Обнаружено при
  написании тестов связки прокачки. `row` стал явным параметром, вызывающие
  обновлены.
- **Элит-комбо: находка снята, код был прав.** Я записал, что `eliteComboCost`
  не соблюдает правило «+15k, если получены прокачкой». Проверка показала
  обратное: `some()` даёт ровно то поведение, которое подтвердил владелец
  2026-08-21 — надбавка берётся, если комбинация **сложилась** прокачкой, и не
  берётся, если игрок имеет её с рождения. Неважно, прокачаны оба навыка или
  один был стартовым. Прогнано на реальных позициях: Gnome Lineman и
  Bloodspawn начинают с комбинацией и платят 0; Amazon Linewoman, добравшая
  недостающий навык, платит 15k. Правило закреплено тестами
  (`test/roster-elite-combos.test.mjs`), чтобы его не «починили» обратно.

- **Автосохранение ростера падало в реальном браузере (P0).** `scheduleSave()`
  в `src/data/roster-store.mjs` вызывала `deps.setTimeoutFn(...)` как метод
  объекта `deps` — нативный `setTimeout` в браузере (в отличие от Node)
  требует `this === window` и кидает `TypeError: Illegal invocation`.
  131 тест это не ловил: они гоняются в Node, где `setTimeout` к получателю
  не чувствителен. Обнаружено при браузерном смок-тесте задачи 6.6 (первый
  раз, когда `saved-roster.mjs` реально открыли в браузере после задачи 5).
  Почищено `.bind(globalThis)` в значениях по умолчанию — отдельный коммит,
  не входит в механический перенос 6.6.

## Глобальные ограничения

- **Стек не меняется:** vanilla JS, нативные ES-модули (`<script type="module">`), никаких бандлеров, транспиляторов, фреймворков и новых рантайм-зависимостей на фронте. Единственная зависимость сервера остаётся `pg`.
- **i18n-правило из `CLAUDE.md` действует без исключений:** любая новая строка интерфейса идёт через `t("ключ")` + `src/i18n/{en,ru}.json`. Доменные функции возвращают **коды** нарушений (`ROSTER_MIN_PLAYERS`), а не готовый текст.
- **Правило зеркальности контента из `CLAUDE.md` действует:** `content/Gata/` и `content/Gata-ru/` должны иметь одинаковые имена файлов и папок после любой правки контента.
- **Перед коммитом контентных изменений:** `npm run build && npm run i18n:check` — одинаковое число страниц для обоих локалей, 0 фолбэков.
- **Данные пользователей священны.** Ни одна задача не имеет права терять сохранённые ростеры. Любая миграция данных выполняется только после дампа (задача 0) и только с проверкой «прогон миграции дважды даёт тот же результат».
- **Поведение UI не меняется до задачи 8.** Задачи 1–7 — механические: перенос кода, извлечение функций, удаление мёртвого. Если после задачи 7 экран выглядит или ведёт себя иначе — это регрессия, а не улучшение.
- **Тесты вводятся только для `src/domain/**` и миграций** (встроенный `node:test`, без внешних зависимостей). UI и экраны по-прежнему проверяются вручную через `npm run dev`.
- **Каждая задача заканчивается рабочим приложением.** `npm run build && npm start`, открыть `http://localhost:3002`, пройти дымовой сценарий из задачи 1.
