# Этап 04 · Дизайн-система в коде — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** перевести сайт на токены, шрифты и палитры 3.0 и дать будущим экранам библиотеку компонентов `src/ui/*`, не сломав ни одного экрана 2.x.

**Architecture:** `src/styles/tokens.css` переписывается по `tokens.json` и объекту `PALETTES` прототипа настроек: режим (`data-mode`) задаёт статусные цвета, палитра (`data-palette`) — поверхности, текст и акцент. Старые переменные 2.x живут во временном `src/styles/legacy-aliases.css` и указывают на новые токены, поэтому старые экраны сразу рисуются в 3.0 без правки их CSS. `src/theme-boot.js` (классический блокирующий скрипт) ставит палитру до первой отрисовки, `src/core/theme.mjs` хранит выбор в `gata-league-palette` и один раз переводит старую тему 2.x. Компоненты — чистые функции `render…(props) → string` плюс `wire…(root)` на делегированных обработчиках, стили — отдельный CSS на токенах рядом с модулем.

**Tech Stack:** vanilla ES-модули в браузере, Node 22 (`node --test`, `node:vm`), CSS custom properties и `color-mix()`, нативный `<dialog>`.

**Spec:** `docs/superpowers/specs/2026-10-14-redesign-design.md` — §0.7, §3.5, §5 (авторитет). Спека выката `docs/superpowers/specs/2026-10-14-redesign-rollout-design.md` — §1.2, §5.4. Мастер-план `docs/superpowers/plans/2026-10-14-redesign-rollout.md` — Global Constraints, протокол этапа, «Дополнения к этапам → 04». План 3.0 `docs/superpowers/plans/2026-10-14-redesign.md` — этап 4. Handoff `docs/redesign/handoff-0.9.1/`: `design-system/README.md`, `tokens.json`, `components/*/README.md`, `components/bundle.css`, `prototypes/mobile/Settings.html` (`PALETTES`), `PR-CHECKLIST.md`.

## Global Constraints

- Ветка `rd/04-tokens` от `origin/redesign` (`d549ff4`), PR в `redesign` по протоколу мастер-плана (шаги 6–10). В задачах ничего не пушить.
- Vanilla ES-модули, без фреймворка, сборщика и TypeScript; без новых зависимостей.
- CSP прода: `default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; …` — ни inline JS, ни `style="…"`, ни `on…=` в разметке; `theme-boot.js` остаётся внешним классическим скриптом.
- Каждая строка интерфейса — через `t("key")` или `data-i18n*`; ключ есть и в `src/i18n/en.json`, и в `src/i18n/ru.json`, без дублей.
- `escapeHtml` на каждую интерполяцию строки. Пропс с суффиксом `Html` — разметка из другой функции `render…()`, вставляется как есть; ничего от пользователя туда не передаётся.
- Бюджеты `scripts/check-budgets.json`: 600 строк на файл, 80 на функцию, 0 недостижимых функций; только уменьшаются.
- Числа и правила — из `src/domain/**` и `content/Gata/**`; вид — из прототипов. Разметка и инлайн-стили прототипов — только образец, в код не копируются. Компоненты `src/ui` не знают правил: цены, лимиты, SPP и причины отказа передаёт вызывающий.
- Брейкпоинты: мобильная раскладка до 900px (`max-width: 900px`), десктоп от 901px (`min-width: 901px`).
- Этап не переносит экраны: CSS 2.x не правится, кроме точечной замены значения на токен там, где алиас не может служить (Task 4, Task 14). `src/shell/` — этап 05.
- Шрифты уже лежат в `assets/fonts/ui/` (релиз 2.1.0) — не копировать заново. Comfortaa и Nunito (`src/styles/fonts.css`, `assets/fonts/comfortaa|nunito`) удаляет этап 13.
- Комментарии в коде — по-английски, в тоне соседних файлов. Ответы владельцу — по-русски.
- Каждая задача — один коммит с тестами. Перед `npm test` всегда `npm run build` (тесты читают `public/data.*.json`).
- CSS компонентов задаёт шрифт, рамку, фон, `text-transform` и `font-weight` явно: глобальные правила 2.x (`button, input { font: inherit }`, `h1…h6 { font: 800 var(--display-font) }`, `option {…}` в `shell.css`) живут до этапа 13.

## Review Focus

1. **Переменная 2.x без алиаса** → объявление молча становится недействительным (у `body` пропадает фон, у карточек — рамки). Task 4, тест «every variable a stylesheet reads is defined».
2. **Мусор в localStorage** — битый JSON, массив, число, `"constructor"` / `"__proto__"` вместо id темы → загрузка не падает и все три читателя (`theme-boot.js`, `theme.mjs`, страница техобслуживания) выбирают одну и ту же палитру. Task 5 и Task 6, матрица `test/helpers/theme-cases.mjs`.
3. **localStorage бросает исключение** (приватный режим, запрет cookies) → `theme-boot.js` ставит палитру по системе, выбор в шапке работает до перезагрузки. Task 6 (vm с бросающим storage), Task 5 («a browser that refuses storage still switches palettes»).
4. **Тренер выбрал палитру в 3.0, а `gata-league-theme` 2.x остался** → перезагрузка не возвращает старую тему. Task 5, тест «a 2.x theme is migrated once and then left alone».
5. **Имя команды или игрока с `<`, `"`, `&`, `'`** в пропсах компонента → текст и атрибуты экранированы, разметка не ломается, лишних элементов нет. Tasks 8–13, строка `HOSTILE` в каждом наборе тестов.

## Решения этого плана

Источники оставили их открытыми; план принимает их так (контроллер подтверждает до исполнения):

1. **Поля `PALETTES` → токены:** `header→--header`, `page→--page`, `desk→--desk`, `card→--surface`, `s2→--surface-2`, `track→--surface-3`, `segOn→--seg-on`, `ink→--ink`, `muted→--muted`, `faint→--faint`, `line→--line`, `ring→--line-strong`, `field→--field`, `off→--control-border`, `acc→--accent`, `accText→--accent-text`, `tint→--accent-tint`, `tintInk→--on-accent-tint`. В тёмных палитрах значения `PALETTES` важнее тёмных значений `tokens.json` (`surface-2` у «Под прожекторами» — `#1B2B23`, как на странице техобслуживания).
2. **Статусные цвета следуют режиму, не палитре** (README ThemePicker): `danger*`, `warn*`, `disabled`, `scrim`, новый `--on-danger` — из `tokens.json` по режиму.
3. **Производные токены** через `color-mix`: `--ink-2`, `--accent-ink`, `--accent-tint-soft`, `--header-muted`, `--header-tab` — `PALETTES` их не даёт, а палитр восемь. Новые токены `--header`, `--page`, `--desk`, `--field`, `--seg-on`, `--accent-text`, `--on-accent`, `--on-danger`. `--pitch-900` остаётся постоянным (бейджи `pos-blitzer`, `cat-general`); шапка и тёмная кнопка берут `--header`.
4. **Алиасы 2.x** — отдельный файл `src/styles/legacy-aliases.css` (этап 13 удаляет его целиком). `--line`, `--muted`, `--accent`, `--danger` совпадают по имени с токенами 3.0 и просто получают новые значения. `--radius: 0` → `var(--radius-md)` (10px). Декоративные сетки и свечения 2.x → `transparent`. Подпись героя главной (`.league-hero-copy p`) переходит с `--bone` на `--ink-2`: на светлой поверхности кремовый текст не читается.
5. **Шрифты:** старые экраны сразу переходят на Golos Text / Oswald через алиасы `--body-font` / `--display-font`. Preload: Golos Text 400 и 600, Oswald 700, latin + cyrillic (6 файлов, ~58 КБ против 49 КБ Comfortaa). Oswald 700, а не 600: в `tokens.json` все стили display, кроме `team-name`, — 700, заголовки 2.x с весом 800 тоже берут файл 700; `team-name` 600 появится в шапке этапа 05 — тогда и его preload. `fonts.css` подключается отдельным `<link>` с `?v=` (relative `url()` внутри не переживут инлайнинг в `styles.css`).
6. **Запись кеша:** `gata-league-palette` пишет только `theme.mjs` (при выборе и при переводе старой темы); `theme-boot.js` только читает. `gata-league-theme` не удаляется: при откате на 2.1 тренер увидит свою старую тему.
7. **Переходный выбор в шапке:** `#theme-select` получает 9 пунктов — «Как в системе» и 8 палитр в двух `optgroup`; значения `system` и `<mode>:<key>`. В режиме «Как в системе» сохраняются ранее выбранные светлая и тёмная палитры. Этап 05 удаляет `#theme-select` вместе с этой разметкой.
8. **`preferences` (API — этап 03 на параллельном треке):** здесь — только чистое отображение выбора на ключи спеки §3.5 (`themePreferences`, `choiceFromPreferences`) и `setThemeChoice()`. Запись «при первом входе, если пусто» и чтение настроек с сервера подключает этап 05 (вход, `#/settings`; зависит от 04 и 03).
9. **Английские названия палитр:** Perfect Conditions, Sweltering Heat, Blizzard, Imperial Nobility (светлые); Under the Floodlights, Dark Elves, Flames of Chaos, Pouring Rain (тёмные). Погодные — как в `content/Gata/General Information/Weather.md`. Русские — из прототипа.
10. **Доступность компонентов отличается от `bundle.css`:** единичный выбор (SegmentedControl, OptionCard) — `role="radiogroup"`/`role="radio"` + `aria-checked` со стрелками; отказавший «+» — `aria-disabled` с причиной в `title`, а не `disabled` (правило `staff-control.mjs`); фокус — `outline`, чтобы не стирать inset-кольца; Sheet — нативный `<dialog>`, который экран показывает через `patchWithModal()` из `components/dialog.mjs`, а не абсолютный scrim.
11. **Компоненты общие, без логики экранов:** StatusChip и MatchCard получают уже переведённые подписи; ResourceCounter — кнопки 44px (правило «нажимаемый элемент от 44 px» важнее 34px прототипа); TextField без индикатора пароля (этап 05, смена пароля); OptionCard без вариантов «категория» и «характеристика» (этап 07d).
12. **Страницы-галереи компонентов нет.** Классы разметки проверяет тест покрытия стилями (`assertStyled`), вид — этап 05, когда оболочка их использует.
13. **Тестовый набор:** `test/helpers/fake-dom.mjs` получает строгий мини-парсер HTML (бросает на любой нестрогой разметке), селекторы, события и `<dialog>`.
14. **Проверка экранов:** реальный сервер (`npm start`, пустая локальная база + админ из `.env`) для публичных и админских экранов, mock API (`scripts/mock-api.mjs`, 5174/5175) для экранов тренера с данными. Подготовка и итоги матча локально не открываются (сидер сломан до этапа 02a, п. 2.7) — их проверяет репетиция M1.

### Task 2: fake-dom — разбор разметки, селекторы, события

Компоненты возвращают строки; чтобы тесты проверяли структуру, а не регулярки по тексту, fake-dom учится разбирать ту строгую разметку, которую пишет `src/ui`, и бросает на всём остальном.

**Files:**
- Modify: `test/helpers/fake-dom.mjs` (шапка-комментарий: «no parser» → описание строгого парсера)
- Create: `test/fake-dom.test.mjs`

**Interfaces:**
- Produces:
  - `parseHtml(document, markup: string) → FakeElement` — контейнер с `tagName === "FRAGMENT"`, его дети — разобранные узлы верхнего уровня.
  - `fireEvent(target, type: string, init?: object) → event` — событие `{type, bubbles: true, defaultPrevented, cancelBubble, preventDefault(), stopPropagation(), ...init}`, уже отправленное.
  - `FakeElement`: `matches(selector)`, `closest(selector)`, `querySelector(selector)` (общий; три прежних формы работают), `querySelectorAll(selector) → FakeElement[]` (массив), `hasAttribute(name)`, `classList` (`contains/add/remove/toggle` поверх атрибута `class`), `addEventListener(type, fn)`, `removeEventListener(type, fn)`, `dispatchEvent(event) → boolean`, `showModal()`, `close()`, `get open`.
  - `FakeDocument`: `documentElement` (элемент `html`, `body` — его ребёнок), `querySelector` / `querySelectorAll` через `documentElement`.

- [ ] **Step 1: Падающий тест** — `test/fake-dom.test.mjs`:

```js
import assert from "node:assert/strict";
import test from "node:test";

import { createDocument, fireEvent, parseHtml } from "./helpers/fake-dom.mjs";

const document = createDocument();

test("markup becomes a tree a test can query", () => {
  const root = parseHtml(document, `<div class="g-a g-b" data-x="1 &amp; 2">
    <button type="button" disabled>Go &lt;now&gt;</button>
    <input value="&quot;q&quot;" required>
    <svg viewBox="0 0 24 24"><path d="M1 1"/></svg>
  </div>`);
  assert.equal(root.tagName, "FRAGMENT");
  const div = root.querySelector("div.g-a.g-b");
  assert.equal(div.getAttribute("data-x"), "1 & 2");
  assert.ok(div.classList.contains("g-b"));
  assert.equal(root.querySelector("button[disabled]").textContent, "Go <now>");
  assert.equal(root.querySelector("input").value, '"q"');
  assert.ok(root.querySelector("input").hasAttribute("required"));
  assert.equal(root.querySelector("svg path").getAttribute("d"), "M1 1");
  assert.equal(root.querySelectorAll("div, button").length, 2);
  assert.equal(root.querySelector('[data-x="1 & 2"] button').getAttribute("type"), "button");
  assert.equal(root.querySelector("path").closest("div"), div);
  assert.equal(div.childNodes.length, 3, "whitespace between tags is dropped");
});

test("broken markup is refused, not guessed", () => {
  for (const bad of ["<div><span></div>", "<div>", "</p>", "<a href='x'>a</a>", "<a href=x>a</a>", "<!-- c -->", "<script>x</script>"]) {
    assert.throws(() => parseHtml(document, bad), /parseHtml/, bad);
  }
});

test("an unsupported selector throws instead of matching nothing", () => {
  assert.throws(() => parseHtml(document, "<p></p>").querySelector("p:first-child"), /selector/);
});

test("events bubble to ancestors, carry currentTarget and can be stopped", () => {
  const root = parseHtml(document, `<section><div><button type="button">x</button></div></section>`);
```

```js
/** Parse render output and attach it, so focus and closest() behave as on a page. */

/** No style attribute, no on* handler, no script: the site's CSP refuses all three. */
export function assertCspSafe(fragment) {
  for (const node of fragment.walk()) {
    if (node.nodeType !== 1) continue;
    assert.notEqual(node.tagName, "SCRIPT");
    for (const { name } of node.attributes) {
      assert.notEqual(name, "style", `${node.tagName} carries a style attribute`);
      assert.ok(!name.startsWith("on"), `${node.tagName} carries ${name}`);
    }
  }
}

/** Every g-* class in the markup is defined in base.css or one of the named src/ui stylesheets. */
export function assertStyled(fragment, ...sheets) {
  const css = ["base.css", ...sheets].map((sheet) => read(`src/ui/${sheet}`)).join("\n");
  for (const node of fragment.walk()) {
    if (node.nodeType !== 1) continue;
    for (const name of (node.getAttribute("class") ?? "").split(/\s+/).filter((part) => part.startsWith("g-"))) {
      assert.match(css, new RegExp(`\\.${name}(?![\\w-])`), `.${name} is not styled`);
```

### Task 10: Sheet на нативном dialog, ProgressDots, OptionCard

Sheet — тот же `<dialog>`, что у `components/dialog.mjs`: экран кладёт `renderSheet(…)` в свою разметку и показывает его `patchWithModal(root, markup, "#" + id)` — тот сохраняет модальность и фокус при перерисовке. До 900px — шторка снизу, от 901px — модальное окно по центру.

**Files:**
- Create: `src/ui/progress-dots.mjs`, `src/ui/progress-dots.css`, `src/ui/sheet.mjs`, `src/ui/sheet.css`, `src/ui/option-card.mjs`, `src/ui/option-card.css`, `test/ui-sheet.test.mjs`
- Modify: `src/styles.css`, `src/i18n/en.json`, `src/i18n/ru.json`

**Interfaces:**
- Consumes: `delegate`, `escapeHtml`, `t`; `renderIconButton` (Task 8); `wireRadioGroups` (Task 8); `classNames`, `dataAttributes`.
- Produces:
  - `renderProgressDots({total, done, label}) → string` — `<div class="g-progress">`: `g-progress__dots` (`aria-hidden="true"`, `total` штук `g-progress__dot`, первые `done` — ещё `g-progress__dot--on`; `done` зажат в `0..total`) и `g-progress__caption` = `t("ui.progress.caption", {label, done, total})`.
  - `renderStepDots({current, total}) → string` — `<div class="g-steps" role="img" aria-label="${t("ui.sheet.step", {current, total})}">`, точки `g-steps__dot`, до текущей — `--done`, текущая — `--now`.
  - `renderSheet({id, title, sub = "", step = null, canGoBack = false, bodyHtml, footHtml = "", wide = false}) → string` — `<dialog class="g-sheet[ g-sheet--wide]" id aria-labelledby="<id>-title">` → `g-sheet__panel` → `g-sheet__handle` (`aria-hidden`), `<header class="g-sheet__head">` (кнопка «назад» `renderIconButton({icon: "back", label: t("ui.sheet.back"), data: {sheetBack: ""}})` или `<span class="g-sheet__spacer">`; `g-sheet__titles` с `<h2 class="g-sheet__title" id="<id>-title">` и `<p class="g-sheet__sub">`; кнопка «закрыть» `renderIconButton({icon: "close", label: t("ui.sheet.close"), data: {sheetClose: ""}})`), при `step` — `renderStepDots(step)`, `<div class="g-sheet__body">bodyHtml</div>`, при `footHtml` — `<footer class="g-sheet__foot">`. Атрибута `open` нет.
  - `wireSheets(root, {onClose = () => {}, onBack = () => {}} = {}) → () => void` — один путь закрытия: клик по `[data-sheet-close]`, клик по самому `dialog.g-sheet` (`event.target === dialog`, то есть по подложке), `keydown` `Escape` внутри шторки (`preventDefault()`, чтобы браузер не закрыл сам) → `dialog.close()` и `onClose(dialog.id)`; клик по `[data-sheet-back]` → `onBack(dialog.id)`.
  - `renderOptionCard({value, title, sub = "", pill = "", radio = false, selected = false, disabled = false}) → string` — `<button type="button" class="g-option" role="radio" aria-checked data-option-value [aria-disabled="true"]>`: при `radio` — `<span class="g-option__radio" aria-hidden="true">` первым, `g-option__text` (`g-option__title`, `g-option__sub`), при `pill` — `g-option__pill` последним. Отключённая карточка — не `disabled`: остаётся в фокусе и показывает причину в `sub`.
  - `renderOptionList({label, options, selected}) → string` — `<div class="g-options" role="radiogroup" aria-label>`; у выбранной `aria-checked="true"`, `tabindex="0"` у выбранной или у первой доступной, у остальных `-1`.
  - `wireOptionLists(root, onSelect: (value, list) => void) → () => void` — `wireRadioGroups` с `group: ".g-options"`, `item: "[data-option-value]"`, `attribute: "data-option-value"`.
