# Этап 11 · Справочник и главная гостя — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** перенести справочник на 3.0 — разделы и поиск `#/ref`, списки `#/ref/:section` (навыки с фильтром по категории), статьи `#/<slug>` в режиме чтения на десктопе, правила команд с командами лиги этой расы — и дать гостю главную `#/` по §7.10; полоса поиска 2.x уходит.

**Architecture:** что лежит в справочнике и в каком порядке, решает чистая модель `src/screens/ref/catalog.mjs` (группы, разделы, порядок статей, поиск страницы по имени) и чистый поиск `search.mjs`; оба получают данные аргументом и тестируются на настоящих `public/data.*.json`. Экраны `src/screens/ref/*` собирают разметку из `src/ui` и рисуют её через `patch()`: одна разметка на обе ширины, на десктопе — полоса-заголовок с поиском, оглавление слева и статья по центру (у навыков и черт — список и панель), на мобайле — ссылка «назад» и статья. Контент страниц (`page.html` из сборки) вставляется как есть внутрь `.g-prose`, а таблицы сборки получают стили на токенах 3.0 в `prose.css`. Главная гостя `src/screens/home/guest.mjs` читает публичный `/api/season`.

## Решения этого плана

Источники оставили их открытыми; план принимает их так (контроллер подтверждает до исполнения):

1. **Модули — по спеке §6:** `src/screens/ref/*` и `src/screens/home/guest.mjs`. Чистое (`catalog.mjs`, `search.mjs`) отделено от экранов; память экрана (запросы, фильтры, кубик) — `memory.mjs`.
2. **Группы и их порядок — из `mobile/Ref.html`:** «Перед матчем и в игре» (Weather, Kick-off Table, Prayers to Nuffle, Casualties, раздел Inducements) → «Игроки» (Player Advancement, Skill Table, разделы Skills и Traits) → «Команды» (раздел «Правила команд», Special Rules, раздел Star Players, Leagues) → «Лига» (All Gata Changes, раздел «Правила лиги»). Спецификация интерфейса §24–26 перечисляет группы в обратном порядке: ряд вкладок прототипа рисуется справа налево, список групп — нет. Порядок совпадает с 2.x (четыре таблицы матча первыми). Названия страниц — из контента (английские в обоих словарях, глоссарий); описания — существующие `preview.<page.id>` и `section.*Description`.
3. **`#/ref/rules` — «Правила лиги»:** сначала семь карточек обзора 2.x (`#/overview/:slug`, «Кратко»), затем пять страниц `Rules/*` («Полный текст»). Почему: карточки обзора жили на главной 2.x, которую гость больше не видит, а страницы регламента в 2.x находил только поиск. Шпаргалок в данных нет: `#/ref/cheatsheets` рисует пустой список и в группы не входит. Reference Sources и корневая страница, как в 2.x, вне групп — их находит поиск.
4. **Поиск заменяет полосу 2.x.** Уходят `#ref-search` с `#global-search` (`index.html`), слушатель в `app.js`, `showSearch` модели оболочки, правила `.g-searchbar*` и `state.query`. Глобальное поле — на `#/ref` (обе ширины) и в полосе-заголовке каждого экрана справочника на десктопе; набор вне `#/ref` переносит туда с запросом и фокусом. У списков — своё поле («Найти навык»), у каждого раздела свой фильтр. Запросы живут в памяти страницы (`memory.mjs`): переживают уход в статью и возврат, перезагрузка их забывает; в адрес и localStorage не пишутся.
5. **Одна разметка, CSS на 900/901.** Полоса-заголовок и оглавление — только десктоп (на мобайле полоса видна только на `#/ref`); ссылка «назад» — только мобайл. Десктоп: `#/ref` — группы сеткой в две колонки без оглавления (индекс сам оглавление); разделы — оглавление и список; статьи — оглавление и статья (до 820px) с «пред./след.» среди статей групп; навыки и черты — оглавление, список и панель (`DeskRef`): адрес статьи `#/skills/<slug>` отмечает строку и открывает её в панели, `#/ref/skills` показывает в панели подсказку. На каждом экране ровно один `h1`: на `#/ref` — заголовок полосы, в разделе — название раздела, в статье и в панели — название страницы; заголовок полосы вне `#/ref` и подпись списка рядом с открытой статьёй — не заголовки (роутер объявляет первый `h1, h2`).
6. **Контент рисуется как есть внутри `.g-prose`** (решение о санитизации — в Global Constraints). Четыре класса таблиц сборки (`fit-cell`, `center-cell`, `number-cell`, `fit-table`) получают стили на токенах в `src/screens/ref/prose.css` под `.g-prose` — справочник больше не зависит от `roster.css` (там глобальные `.fit-cell` и `.center-cell` остаются для таблиц состава 2.x до этапа 07). Таблица `fit-table` (до пяти колонок) — во всю ширину без прокрутки и на 390; таблица шире прокручивается внутри своей рамки, страница вбок не едет.
7. **Особые тела статей.** Карточки 2.x для Kick-off и Prayers на мобайле уходят: это таблицы в две-три колонки `fit-table`. Leagues сохраняет тело «доступ к лигам» (переезд в `ref/bodies.mjs`, вид 3.0). Skill Table: на мобайле — списки по категориям с номерами граней D16, на десктопе — таблица контента; кубик остаётся (вопрос владельцу 3): исход равновероятен по колонке — это D16 с перебросом пустых граней (спека §3.4), поэтому подпись «D16» и номер грани честны; бросок локальный (`Math.random`): это игрушка справочника, а не бросок прокачки, который делает только сервер (§3.4).
8. **Правила команды — из `page.team`, не из HTML контента:** позиции (кол-во, цена, характеристики, навыки, доступ Primary / Secondary) — карточками на мобайле и таблицей 3.0 на десктопе; строки «Уровень» (`meta.league`), «Рероллы» (`meta.rerolls`), «Апотекарий» (`teamApothecaryAccess`), «Доступ к лигам» (`teamLeagueOptions`); особые правила — имена из `teamSpecialRuleTokens` (Team Captain у всех), текст — раздел страницы Special Rules, разрезанной по `<h3>` (заголовки английские в обоих словарях; `Favoured of X` берёт раздел `Favoured of...`). «В лиге играют» — строки `/api/season` с тем же `baseTeamSlug`, без выбывших, по месту: «N-е место · очков: P» (В/Н/П в ответе сервера нет). Тренеру строка ведёт на свою команду (`teamUrl`) или на команду соперника (`playerTeamUrl`); гостю — без ссылок (вопрос владельцу 2). Ряд чипов рас (37 рас) и вводный абзац прототипа не рисуются: в контенте абзаца нет, список рас — одно нажатие. 9. **Навык и черта в панели:** знак категории (буква на `--cat-*`, у черты «•» на `--cat-trait`) — локальный класс `g-ref-badge`, NumberBadge в `src/ui` — дело следующих этапов; подпись «Agility · Active» из тегов страницы; правило — HTML контента; «Случайный бросок» — категория и грань D16 из `data.skillGroups` (через `canonicalSkillName`), иначе «Нет в таблице навыков»; «В нашей команде» — у тренера с активной командой: игроки `activeTeam().roster`, которым навык дают позиция, прокачка, Favoured или капитанство (`heldSkillKeys`), номер, имя, позиция. «Элитная комбинация» не рисуется (вопрос владельцу 1).
