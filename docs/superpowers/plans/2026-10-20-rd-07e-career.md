# Этап 07e · Состав: карьера по матчам — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** «Карьера» по матчам приходит туда, где её ещё нет. В панель «Состава» на десктопе (`DeskRosterCareer.html`) — у живого игрока под парой действий, у погибшего на месте строки «Карьера: N SPP». И к погибшему: на телефоне и на странице 07b — блоком `PlayerCareer`, на месте `PlayerDead`. История перечитывается, когда сервер ушёл вперёд: кончился или начался матч, пришёл ответ на тап, легло сохранение. Строки карьеры честно читают оставленного journeyman и гибель без тапов. Лидеры обзора считают карьеру (`careerCounters`), как «Состав». Всё — так близко к прототипам, как позволяет код, и готово к вехе M2.

**Architecture:** ни сервера, ни миграций: `GET /api/teams/:id/players/:pid/history` есть с этапа 03 и отвечает и про погибшего, `GET /api/teams/:id/events` — с 02b/03. Блок «Карьера» 07d (`src/screens/team/roster/career.mjs`) становится общим: одна разметка в двух формах — телефонной (`PlayerCareer`: кнопка-заголовок, итоги, шапка списка, строки, сноска) и десктопной (`DeskRosterCareer`: кнопка-заголовок и строки). Его стили уходят из `profile.css` (они там только до 900px) в свой `career.css` без брейкпоинта. Чтения визита становятся словарём по игроку (`visit.careers`): у каждого чтения есть отметка (`stamp`) того, что сервер знал, когда его просили. Отметка — ревизия очереди, номер чтения состава, число услышанных тапов, матч. Ушла отметка — чтение повторяется, прежние строки стоят до ответа. Десктоп читает, только пока список открыт, и только игрока панели. Погибший — тот же блок через новый слот `careerHtml` у `fallenProfileMarkup`. Лидеры обзора читают неучтённые записи один раз за визит и при смене игр; ревизия записей должна совпасть с ревизией команды в списке.

**Tech Stack:** vanilla ES-модули, хешевый роутер, Node 22 (`node --test`), `test/helpers/fake-dom.mjs`, `fake-api.mjs`, `ui.mjs`, `contrast.mjs`, `roster-page.mjs`, `ref-screen.mjs` (`withWindow`); CSS custom properties; `npm run screens`, `scripts/mock-api.mjs`.

Начатый матч так же даёт свою строку. Тесты:
   - Task 3: «a match that ends while the profile is open: the roster read again, then the history; the rows stand meanwhile, then the match is confirmed and GP counts it»; «a match begun while the profile is open reads it again: its row waits for the post-match».
2. **Десктоп в матче, список открыт, тренер тапает.** Ожидание: ответ на тап — одно новое чтение истории. Пока тап в пути — ни одного. «До записей на сайте» считается от SPP того же мгновения, что и строки (`basis`): строка «+3» не появляется и не пропадает на каждый тап. 3. **На десктопе выбирают другого игрока, пока список открыт или ответ ещё в пути.** Ожидание: у каждого игрока свои строки и одно чтение за визит.
