## Решения этого плана

Источники оставили их открытыми; план принимает их так (контроллер подтверждает до исполнения).

**Создание и набор**

1. **Команда создаётся одним `POST /api/teams` по «Сохранить команду».** Кнопка «Создать «…»» шага «Новая команда» открывает набор и на сервер не пишет.

   Почему: до этапа 12 новые команды — `active`, а в `active` сервер отклоняет рост Start Re-rolls (`STAGE_PURCHASE_LOCKED`, `stageViolations`). Пустую команду, созданную по «Создать», нельзя добрать `PATCH`-ами: тренер потерял бы Start Re-rolls по 60k. `POST` стадию не проверяет (спека 3.0 §3.1).

   Этап 12 вместе со стадией `draft` переносит создание на «Создать» и делает набор автосохранением черновой команды (вопрос владельцу 1).
2. **Набор живёт только в памяти модуля** `src/screens/teams/new.mjs` и привязан к тренеру (`userId`).
   - Переход по сайту и возврат на `#/teams/new` его сохраняют.
   - Перезагрузка и закрытие вкладки, пока в наборе есть игроки или персонал, спрашивают (`beforeunload`).
   - Выход и другой тренер начинают с нуля.

   Значение старого ключа `gata-league-builder-draft` не читается. Его стирают при открытии `#/teams/new`: в нём может лежать логотип почти на 2 МБ (`RETIRED_KEYS`, Task 9).
3. **`#/teams/new` — только для вошедших и со своей рамкой** (`bare`, как вход): без шапки, вкладок и SideNav, как `Builder.html` и `DeskBuilder.html`. Гость идёт ко входу и возвращается сюда.

   Шаг «Новая команда» (название и раса) — страница этого адреса, а не шторка над обзором, как в `TeamNew.html`. Почему: у адреса должен быть первый шаг. На него ведут редирект `#/builder`, «Создать команду» пустого обзора, «Новая команда» переключателя и перезагрузка.
4. **Перерасход бюджета при наборе разрешён и виден**, как в `BuilderOver.html`:
   - красная полоса и «Перерасход 220k», сохранение выключено;
   - «+» отказывает только на максимуме позиции (`POSITION_MAX`) и на 14 игроках (`ROSTER_MAX_PLAYERS`) и говорит причину (решение 14);
   - позиция дороже остатка — «+» серый, но нажимается.
5. **Номер — следующий свободный от 1 до 99 в порядке найма** (`nextFreeNumber`); тренер правит его в «Номерах, именах и капитане». Капитан — одна радиогруппа, второго не бывает (`setRosterCaptain`).
6. **Логотип — файл до 2 МБ**: `logoUploadMaxBytes` в `src/core/logo-upload.mjs`, а не 2,9 MB прототипа (число из кода, §0.1). Сервер принимает data URL до 2 900 000 байт.
7. **Подписи под персоналом — по коду и этапу.**
   - Пока новые команды `active`: «В наборе Start Re-rolls стоят 60k. После сохранения команды докупить можно только Team Re-rolls по 120k».
   - Строка прототипа «Состав можно менять до первого матча» не выводится: в коде такого правила нет. Этап 12 перепишет подпись.

  - `standingOf(seasonData, teamId) → {rank, points, of}|null`:
    - строка `standings` команды без `withdrawnAt`;
    - `of` — число строк таблицы без `withdrawnAt`;
    - нет строки или `seasonData` — `null`.

    - матчи лиги этого сезона с соперником, по `roundNumber`;
    - `result` — `gameOutcome` или `null`;
    - `current` — `gameId === currentGameId`.
  - `recentResults(games, teamId, limit) → {gameId, result, opponent, round, friendly, score, cas}[]`:
    - завершённые (`resultKind !== null`) от новых к старым по `confirmedAt ?? updatedAt`;

  - `teamLeaders(savedTeam, raceTeam) → {key: "spp"|"td"|"cas"|"comp", name, number, position, value}[]`:
    - для каждого ключа — игрок с наибольшим значением (`playerSppTotal`, `spp.touchdowns`, `spp.casualties`, `spp.completions`);
    - при равенстве — первый по составу;
    - ключ, где у всех ноль, пропущен;
    - без расы — `[]`.
  - `teamInitials(name) → string` — первые буквы первых двух слов, заглавные; пустое имя — `"?"`.
- Produces (`src/ui/kpi-tile.mjs`):
  - `renderKpiGrid(tiles, {row = false} = {}) → string` — пустой массив → `""` (не `throw`); любое положительное число плиток;
  - `row` → класс `g-kpis--row`;

import { installFakeApi } from "./helpers/fake-api.mjs";
