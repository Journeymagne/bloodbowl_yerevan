# План: редизайн Gata League 3.0

Проектное решение: `docs/superpowers/specs/2026-10-14-redesign-design.md`. Ссылки вида «§3.2» ведут на разделы спецификации.

## Как устроена работа

- **Ветки.** Базовая ветка `redesign` создана от `main` (`dc9a08e`). Каждый этап — это ветка `rd/NN-название` от актуальной `redesign` и PR в `redesign`. В `main` ветка `redesign` вливается одним PR на этапе 13.
- **Синхронизация с `main`.** Раз в неделю или после любого фикса в `main` делаем `git merge main` в `redesign`. Конфликты решаются в `redesign`, а не в этапных ветках.
- **Каждый PR зелёный:**
  ```bash
  npm test && npm run check && npm run i18n:check && npm run build
  npm run smoke                 # и smoke:pre-match / smoke:friendly / smoke:post-match, если этап трогает матчи
  ```
  `npm run build && npm run i18n:check` должны показать одинаковое число страниц EN/RU и 0 fallback (CLAUDE.md).
- **Скриншоты в описании PR.** Для каждого перенесённого экрана нужны снимки на 390 px и 1440 px, плюс тёмная палитра.
- **Миграции.** Применённые файлы не правятся: сервер проверяет checksum. Ошибка в миграции исправляется только новой миграцией.
- **Правила.** Числа берутся из `src/domain/**` и `content/Gata/**`, не из макетов (§0.1).

Отметки: `[ ]` не начато, `[~]` в работе, `[x]` готово. Обновляем их в каждом PR.
