# Этап 10 · Таблица и соперники — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `#/season` рисует таблицу лиги 3.0 вместо вкладок 2.x — на телефоне `League.html`, на десктопе таблица `DeskSeason.html` во всю ширину рядом с «Календарём сезона» (туры и пары лиги); своя строка выделена, строка ведёт на обзор команды, раса — на статью «Правила команд»; «Матчи» десктопа (`#/t/:id/matches`) получают таблицу `DeskSeason` слева от «Календаря», в календаре — другие открытые матчи команды, а «Результаты» телефона — строку отправленного счёта; правая колонка обзора десктопа — мини-таблицу `DeskOverview`; `#/coaches/:uid/teams/:tid` — обзор соперника 3.0 (`OppTeam`, `DeskOppTeam`: место, форма, TV, наша встреча, тренер и Telegram, состав с навыками, шторка навыка с тем, что выпало на кубиках); `#/coaches/:uid` — профиль тренера 3.0 (`CoachProfile`, `DeskCoachProfile`); пункт SideNav «Сезон» тренера с командой ведёт на «Сезон» его команды; всё — так близко к прототипам, как позволяют код и правила владельца.

**Architecture:** таблица — чистые данные над тем, что уже публично отдаёт `GET /api/season`: место, очки и игры — сервера (`standings`, `computeSeasonStandings`), победы, ничьи, поражения, пропущенные TD и CAS и форма — из `rounds[].pairings` по тому же условию, по которому сервер считает матч (`src/data/season-table.mjs`; так же 07d считает разницу обзора — `seasonDifference`). Разметка таблицы — одна на две формы ширины (`src/screens/season/table.mjs`), её берут страница лиги, «Сезон» десктопа и мини-таблица обзора. Обзор соперника и профиль тренера — экраны `src/screens/coaches/*` над `GET /api/players/:uid[/teams/:tid]`, таблицей и играми самого тренера (наша встреча, следующий соперник, ваши встречи — из его `/api/games`, спека 3.0 §4: «обзор соперника … собирается на клиенте»). Состав соперника — те же строки, что у «Состава» (`rosterLines`), шторка навыка — та же (`skillSheetMarkup` + `rollBlockMarkup`). Сервер меняется в одном месте: публичная команда отдаёт `rolls` — использованные броски случайного навыка, только навыки кубиков, без попыток (передача 07d; спека 3.0 §9.5: «видят это все, кто может открыть состав»). Миграций нет.

**Tech Stack:** vanilla ES-модули, хешевый роутер, Node 22 (`node --test`), `test/helpers/fake-dom.mjs`, `fake-api.mjs`, `ui.mjs`, `contrast.mjs`, `api-db.mjs`, `scratch-db.mjs`; CSS custom properties; нативный `<dialog>`; `npm run screens`, `scripts/mock-api.mjs`, `scripts/smoke-api.mjs`.
