## Review Focus

1. **Бросок повторён после сетевой ошибки или запрошен из двух вкладок разом** → тот же бросок, одна строка `dice_rolls`; бросок, на который уже ссылается прокачка, второй раз не принимается (`DICE_ROLL_USED`), а отменённая прокачка не даёт перебросить (Task 5, Task 6).
2. **Тап наперегонки с шагом «Игроки» или с завершением итогов** → проходит ровно одно из двух, записи складываются в сохранённую статистику; правка вне матча либо попала в блоб и учтена, либо отклонена `MATCH_NOT_LIVE`, но не потерялась молча (Task 7, Task 8).
3. **Устаревший или параллельный `POST /treasury` и `PATCH` по одной ревизии** → проходит один, второй получает 409 с командой; казна сдвинулась один раз, журнал объясняет её ровно одной строкой (Task 3).
4. **Двойное нажатие «Отметить гибель» или отмена гибели из матча тренером** → одна строка павшего, игрок снят один раз; `FALLEN_FROM_MATCH` для тренера, админ отменяет (Task 4).
5. **Настройки из двух вкладок и `activeTeamId` чужой команды** → оба ключа сохранились; чужая или выдуманная команда — 404, ничего не записано (Task 10).

## Решения этого плана (контроллер подтверждает)

- **Миграции нет.** «Один неиспользованный бросок на шаг» держит блокировка строки команды: все писатели `dice_rolls` (бросок, сохранение состава) берут её первой. Частичный уникальный индекс не годится — он запретил бы освобождение броска при отмене прокачки, когда у игрока уже ждёт следующий; список бросков по команде не нужен, поэтому и индекс `dice_rolls(saved_team_id)` не нужен.
- **Шаг броска — игрок и назначение.** Пока у игрока есть неиспользованный бросок этого назначения, `POST …/rolls` возвращает его (самый ранний), какую бы категорию ни прислали; новый — только когда прежний использован. Отмена прокачки (ссылка пропала из блоба) снимает `used_at`, и следующий запрос получает тот же бросок. SPP бросок не проверяет: им же воспользуются итоги 09b, где SPP матча ещё не в блобе. `params` броска характеристики — `{sides: 8}`, как у навыка `{…, sides: 16}` и в спеке §3.4 (таблица пуста до этого этапа).
- **Проверка броска — в `writeSavedTeam`** (тренер и админ): новая ссылка `{via: "site", id}` — UUID, строка этой команды и этого игрока, назначение по типу (`random` ↔ `random_skill`, `stat` ↔ `stat`), результат по `grants` (`random`: тот же навык; `stat`: характеристика из `result.stats` или навык вместо характеристики), `used_at IS NULL` → `now()`. Иначе 422 `DICE_ROLL_MISMATCH` или 409 `DICE_ROLL_USED`, ничего не записано.
- **Тап стороны, которая не следует за записями** (сохранила шаг «Игроки» или итоги начаты в 2.x — `followsEvents !== true`), — отказ 409 `EVENT_SIDE_LOCKED`: принятый тап молча стёрла бы разница при завершении. После `reset-side` тапы снова принимаются.
- **«Правка вне матча»** — `POST …/events` без `pairingId`, только пока у команды идёт матч (под блокировкой строки команды); без идущего матча — `MATCH_NOT_LIVE` (вне матча правят состав, и `PATCH` пишет учтённые записи по разнице `spp` без MVP). Травма без матча — `FIELD_INVALID`. `finishPost` переносит неучтённые правки команды в блоб отдельным `UPDATE` после `applyPostMatchRoster` (поэтому `after_roster` — только матч), игроков, которых больше нет, пропускает, а строки учитывает.
- **Карьера по матчам:** матч, завершённый итогами, — разница `before_roster`/`after_roster` этой команды (с MVP и бонусами, ровно то, что получил блоб; для 3.0 и для 2.x одинаково); идущий — записи (`pending`); иначе «без деталей». Правки вне матча — отдельная сумма. Травма — `effectiveInjury` с `gamesPlayed` стороны итогов, без итогов — подсчёт, как в `postSources`. Сумма строк равна карьере для всего, что записано с 3.0.
- **Доступ:** чтения (`ledger`, `fallen`, `events`, `history`) — владелец или админ; записи — владелец; отмена гибели из матча — только админ; `activate` — только админ. Чужая команда — 404 `TEAM_NOT_FOUND`.
- **Тело запроса:** одна ошибка `FIELD_INVALID {field}` (400) для любого негодного поля вместо кода на каждое; `revision` в теле `treasury` и `death` обязательна — нет или не совпала → 409 `TEAM_SAVED_ELSEWHERE` с командой; `DELETE …/fallen/:fid` без ревизии (только возвращает игрока под блокировкой; открытый редактор получит 409 при следующем сохранении).
- **Журнал:** курсор — непрозрачный base64url от `[created_at::text, id]`; `limit` 1…100, по умолчанию 20; ответ `{entries, next, since}`, `since` — `applied_at` миграции 010 («История ведётся с …»). Ручная операция: `delta ≠ 0` до золотого, `|delta| ≤ 100000`, `reason` из пяти, `note` ≤ 200 символов; уход в минус — 422 `ROSTER_BREAKS_THE_RULES` с `violations: [{code: "TREASURY_INVALID"}]`.
- **Павшие:** причина обязательна (≤ 500 символов); снимок — игрок из блоба; возврат проверяет лимиты `checkRoster` (блокирующие нарушения → 422), капитанство возвращается, только если капитана нет.
- **`activate`** идемпотентен (уже `active` → 200 без изменений) и поднимает `revision`, чтобы открытый редактор перечитал стадию; `stage` и `activatedAt` — в `publicSavedTeam`.
- **Пароль:** неверный `currentPassword` (или его нет) — 403 `CURRENT_PASSWORD_WRONG` (не 401: 401 клиент читает как «сессия кончилась») и считается неудачным входом этого логина (`rate-limit.mjs`, 429 после лимита); успешная смена закрывает остальные сессии пользователя, текущая остаётся.
- **Настройки:** `PATCH` — `SELECT … FOR UPDATE` + `mergePreferences` в транзакции, тело — изменяемые ключи, ответ `{preferences}`; `activeTeamId` приводится к нижнему регистру в `checkPreferences`, чужая или несуществующая команда — 404; висячий `activeTeamId` в ответах не показывается.
- Сервер не запрещает `PATCH`, казну и гибель во время матча: §0.11 закрывает их в интерфейсе, `finishPost` по-прежнему отвечает `POST_TEAM_CHANGED`.
- Smoke: казна, павшие, бросок, настройки и пароль — `scripts/smoke-api.mjs` (только HTTP, свой аккаунт); тапы, правка вне матча и карьера — `scripts/smoke-post-match.mjs` (единственный smoke с начатым матчем).
